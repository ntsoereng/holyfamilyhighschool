PREPARE / 01
How to run this workbook
Work through T01-T18 first. These establish a clean baseline. Record screenshots and expected totals
before T19-T30, which deliberately withdraw reports or alter access. Restore the baseline between
independent destructive scenarios.
Role / session Responsibility
Reporting administrator Creates setup records and accounts; reviews marks, generates, checks fees and
publishes. Start with an existing authorised administrator.
Teacher A / Teacher B Each uses a separate teacher account and assigned subject sheets. Administrators
review sheets; teachers enter the marks.
Student / parent / other family Use separate accounts and browser profiles or private windows. A student uses the
family portal role with relationship Student.
Before starting
1. Ask the technical owner to identify the test site and confirm a restorable baseline backup.
2. Use the manual fixture on pages 3-4. Use fresh TEST identifiers for each run; do not reuse real
admission numbers.
3. Record the site URL, date, browser/device and build on page 1. Check school contact details on
held-report pages.
4. Obtain individual test credentials privately. Do not write passwords in this workbook or screenshots.
5. Keep report PDFs and screenshots together under the run date. Note the role, class, quarter and report
revision in each evidence filename.
Outcome When to use it
PASS Actual result matches every expected check; keep evidence.
FAIL A supported feature behaves differently from the expected result.
BLOCKED You cannot execute because access, data or an external dependency is missing.
GAP The school needs a workflow the module does not currently provide.
NOT RUN No test execution or evidence yet. Do not count as a pass.
Where expected results came from
Reviewed against the local implementation on 22 November 2026: academics/README.md, models.py, forms.py,
services.py, reports.py, views.py, urls.py and portal templates. Expected results describe the current build, not a
guarantee that a deployment has passed testing.
Optional existing demo: demo.admin, demo.teacher.maths, demo.teacher.languages, demo.parent and demo.student
may exist on a seeded local copy. Its names, marks and fee states differ from this workbook. Use its actual data for
exploratory tests; use pages 3-4 for exact arithmetic checks. Demo passwords are generated locally and are not printed
here.

Why these are the answers
TEST-001 English: (42 + 76 + 70) / 3 = 62.666..., rounded half up to 63. Mathematics rounds to 68. Its Q3
average is (70 + 56) / 2 = 63.0. The overall result uses this current-quarter average, not the mean of its
final marks (65.5). TEST-001 and TEST-003 tie in the stream.
The final-mark average cell intentionally repeats the configured result average (63.0 here). Check this carefully with staff:
the column label may need clarification even when the current calculation is correct.

PREPARE / 04
Navigation and release rules
Screen / route What to do there
School portal: /portal/ Teacher sheets or student/family report cards, according to
role.
Administration: /portal/office/ Classes, students, subjects, periods, class rosters and teacher
assignments.
Accounts & access: /portal/office/accounts/ Create/review accounts; open family links and teacher
assignments.
Grading policy: /portal/office/policy/ Lookup evaluations, pass mark, result basis and principal name.
Reports & fees: /portal/office/reports/ Select class and quarter; review sheets, details, fee status, PDFs
and publication.
Audit log: /portal/office/audit/ Read the recorded actions and actors.
Family release gate: every requirement must hold
The student and account are active; the family relationship is active and verified; the report is current
and published; a fee review exists with outstanding amount exactly zero and Cleared explicitly checked.
Administrator preview bypasses publication and fees, so it cannot prove student access.
Q3 fee review Cleared? Expected family result after publication
No fee review No Held; contact office to confirm balance.
M 250.00 No Held; show outstanding amount and school contact.
M 0.00 No Held; zero alone does not release the report.
M 0.00 Yes Available if every other release condition is met.
M 250.00 Yes attempted Validation error; cannot clear a positive balance.
Approval and release are separate checks
There is no separate Approved state or Approve button. The administrator checks submissions and
previews, then chooses Publish reviewed reports. Fee clearance controls each student's release. The
same administrator can do all these steps; independent approval is a capability to assess.
Use Q3 for release tests. Complete Q1-Q2 sheets to supply history; generating Q1-Q2 reports is optional until T20. Do not
edit an earlier quarter while measuring the page 4 baseline.
